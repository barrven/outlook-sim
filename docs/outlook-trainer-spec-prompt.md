# Prompt: write a product spec for an Outlook-like Electron training app

Write a detailed v1 product specification for a Windows-only Electron desktop app that trains office employees on email correspondence and calendar/deadline management. The spec should be implementation-ready: purpose, user, scope in/out, information architecture, screens, data model, settings, LLM behavior, scenario packs, persistence, and non-goals.

## Purpose
The app is a practice sandbox that looks and feels like classic Windows Outlook. No real mail is sent or received. All correspondence is mock data generated by an LLM API. The domain is not hardcoded. A system prompt plus personas define the workplace (legal, insurance, medical office, etc.). Example: a personal-injury legal assistant handling clients, insurers, and doctors, collecting information, and hitting documentation deadlines and milestones. Practice only — no scoring, grading, or coaching UI.

## Users and modes
- Trainee: a generic office employee.
- Free-play (default): operator sets system prompt + personas + trainee identity, starts with an empty or lightly seeded mailbox/calendar, LLM improvises replies and unsolicited incoming mail.
- Packaged scenarios: load/save scenario packs that include starting inbox, contacts/personas, calendar deadlines, and optional timed incoming messages.

## UI
Mimic classic Windows Outlook, not New Outlook / Outlook on the web:
- Left folder pane
- Center message list
- Right reading pane
- Top ribbon or classic toolbar
- Mail and Calendar modules in the left navigation
Recognizable Outlook design elements (layout, icons, folder names, compose window) so staff can transfer muscle memory. Do not require a pixel-perfect clone of a specific Office year.

Out of v1: People/Tasks/Notes modules as first-class apps, conversation threading, case-file / matter panel, meeting invite workflow (accept / tentative / decline).

## Mail (v1)
- Compose and mock-send
- Reply, Reply All, Forward
- Drafts
- Delete and Deleted Items
- Folders: Inbox, Sent, Drafts, Deleted Items, plus custom folders
- Read / unread
- Flags
- Categories
- Search
- Mock attachments: filename and placeholder only, no real file payload required
No real SMTP, Exchange, Graph, or IMAP.

## Calendar (v1)
- Views: day, work week, week, month
- Deadlines and all-day items
- Reminders
- Recurring events
Out of v1: appointments-as-meetings with persona attendees and RSVP.

## Time
Use a simulated office clock with start, pause, and speed controls so multi-day deadline scenarios can run in one sitting. Message timestamps and reminder firing follow simulated time, not wall-clock time.

## LLM-generated correspondence
- When the trainee sends or replies, generate a persona reply in that contact’s voice when a reply is appropriate.
- Also generate unsolicited incoming mail (status updates, demands, reminders, new requests) using the system prompt, personas, current mailbox/calendar state, and simulated time.
- Never send traffic outside the app.

## Settings
- Provider + model picker. v1 providers: OpenAI, Anthropic, Gemini, Grok (xAI). Store an API key per provider.
- Trainee identity: display name, job title, From email used on outgoing mock mail.
- One editable system prompt that sets domain, goals, tone, and rules of the simulation.
- Personas (contacts). Each persona has:
  - display name
  - email address
  - role (client, insurer, doctor, etc.)
  - short bio / relationship to the trainee
  - writing-style notes
  - optional extra prompt for that persona
Personas appear as contacts and as From/To parties on mock mail.

## Data and platform
- Windows only
- SQLite for runtime app data (messages, folders, calendar items, flags, read state)
- JSON files for configuration: settings, system prompt, trainee identity, personas, and scenario packs
- Scenario pack JSON must be loadable and savable from the UI

## Spec deliverable format
Produce:
1. One-page overview
2. In-scope / out-of-scope table
3. Screen-by-screen UI spec (Mail, Compose, Calendar, Settings, Scenario load/save, clock controls)
4. Data model (SQLite tables + JSON schemas)
5. LLM prompt assembly (how system prompt, trainee identity, personas, thread, calendar, and simulated time are combined)
6. Unsolicited-mail scheduler behavior
7. Settings and secret-handling notes (do not invent a cloud backend)
8. v1 acceptance criteria

Do not add features that were listed as out of scope. If a decision is missing, state the assumption instead of expanding scope.
